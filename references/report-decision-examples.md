# Report decision examples

이 문서의 분류와 출력 예시는 권고가 아니라 필수 판정 기준이다. 비슷한 응답은 표현에 포함된 단어 하나가 아니라, 아래 예시와 같은 **최종 의미**로 판단한다.

## 1. 긍정과 개선 판정

개선 의견은 운영진이나 강사가 바꾸거나 보완해야 할 **미해결 문제·요청·제안**이 남아 있는 응답이다. 어려움·부족함·복습 같은 단어만으로 개선 의견으로 보내지 않는다.

| 응답 의미 | 판정 | 이유 |
| --- | --- | --- |
| 어려웠지만 수업 중 복습 기회가 있어 도움이 됨 | 긍정 | 어려움이 수업 안에서 해소되었고 별도 변경 요청이 없음 |
| 기다리는 시간이 있었지만 다른 실습을 할 수 있어 괜찮았음 | 긍정 | 응답자가 불편을 최종적으로 수용했고 변경 요청이 없음 |
| 부족한 부분은 스스로 복습·자습하겠음 | 긍정 | 개인 학습 계획이며 운영진에게 요구한 개선이 없음 |
| 타이트하지만 배우는 것이 많아 좋았음 | 긍정 | 최종 평가가 학습 이점에 있음 |
| 뇌가 과부하 올 것 같다는 개인 소감만 남김 | 긍정 | 운영 변경 요청이 없는 개인 학습 소감임 |
| 피드백 시간이 지연되었는데 공지가 없어 방치된 느낌을 받음 | 개선 | 미해결 운영 문제와 공지 요청이 있음 |
| 복습하지 않은 수강생 때문에 진도가 밀린 점이 아쉬움 | 개선 | 수업 진행에 대한 불만이 남아 있음 |
| 실시간 진도를 놓치지 않으면서 보완할 운영 방식이 필요함 | 개선 | 운영 방식 변경을 직접 제안함 |
| 교안을 다운로드할 수 있게 해달라 | 개선 | 직접 요청임 |
| 선택과제를 더 늘려달라 | 개선 | 직접 요청임 |

점수는 분류 기준이 아니다. 5점 응답도 요청이 있으면 개선이고, 2점 응답도 텍스트가 칭찬뿐이면 그 텍스트는 긍정에 둔다. 낮은 점수는 별도로 `특이사항` 후보가 된다.

## 2. 긴 개선 의견 요약

긴 개선 의견의 요약은 첫 문장을 잘라 붙이지 않는다. 칭찬보다 **남아 있는 문제 또는 요청**을 한 문장으로 요약한다. 요약 끝에 `…`를 붙이지 않는다.

아래 원문은 구조 설명을 위한 짧은 가상 예시다. 실제 보고서에서는 원본 셀의 전체 내용을 생략 없이 그대로 넣는다.

좋은 예:

- 피드백 시간이 지연되었으나 공지가 없어 방치된 느낌을 받음 (최미리내님 - 5점)
  - 원문 보기
    - 8/6 4시 10분부터 진행했던 수업은 피그마 개념을 이해하기 쉽게 코치님이 같이 진행해주셔서 좋았습니다
      다만 5시 30분부터 강사님 피드백 시간이었는데, 안내 없이 대기 시간이 발생했습니다.

- 복습하지 않은 수강생 때문에 수업 진도가 밀린 점이 아쉬움 (조수아님 - 콘텐츠 5점·실시간 5점·과제 5점)
  - 원문 보기
    - 수업 정말 좋았어요. 다만 복습 안하고 못하겠다고 하는 분들 때문에 진도가 조금씩 밀리던 때가 있던 게 아쉬워요.

- 실시간 진도를 놓치지 않으면서 부족한 부분을 보완할 운영 방식이 필요함 (최미리내님 - 콘텐츠 5점·실시간 5점·과제 5점)
  - 원문 보기
    - 전반적으로 실습 위주의 수업이라 좋았습니다. 다만 별도 공간에서 도움을 받는 동안 본 수업이 진행되어 흐름을 놓치는 문제가 있었습니다.

나쁜 예:

- `수업 정말 좋았어요!`처럼 칭찬만 요약함
- 원문 앞부분을 복사한 뒤 `…`로 끝냄
- 원문의 문단마다 새 `-`를 붙여 여러 응답처럼 분리함

`원문 보기` 아래에는 한 응답을 목록 항목 하나로 둔다. 원문의 줄바꿈은 같은 목록 항목의 이어지는 줄로 들여쓰며, 새 목록 항목으로 쪼개지 않는다.

## 3. 운만조 필드 라우팅

Profile `sheets.operation` 탭의 문항 위치를 그대로 따른다.

- D `운영만족도 점수를 준 이유`: 일반 운만조 VOC
- E `그 외 기타의견`: 일반 운만조 VOC

두 셀에 서로 다른 유효 의견이 있으면 각각 한 번씩 포함한다. 같은 원문이 중복되면 렌더링 전에 제거한다. 운영 설문에는 수준별 학습반 문항이 없으므로 수준별 학습반 섹션을 만들지 않는다. `없음`, `없습니다`, `따로 없습니다`, 공백 문자만 있는 응답은 피드백으로 출력하지 않는다.

## 4. 특이사항 제목

제목은 긴 원문을 붙여 넣지 않고 사람이 한눈에 알아볼 짧은 문제 유형으로 쓴다.

- 이해 부족, 진도 추종 어려움, 과제 수행 막막함이 확인됨: `학습 부진`
- 여러 학습 만족도 항목이 낮지만 설명이 없음: `전반적 학습 만족도 저조`
- 한 항목만 낮고 설명이 없음: `콘텐츠 만족도 저조`, `실시간 만족도 저조`, `과제 만족도 저조` 중 해당 항목
- 하차 의사: `하차 검토` 또는 확인된 상태에 따라 `하차`
- 출결 문제: `출결 이슈`
- 헬스체크 라벨이 `불만`이고 수업/운영 불만이 본문에 확인됨: `수업·운영 불만`
- 헬스체크 라벨이 `학습고민`이고 이해/적용 어려움이 확인됨: `학습 고민`
- 헬스체크 라벨이 `관심이 필요함`, `하차`, `하차예정`, `수강철회` 중 하나이고 과정 지속 고민이 확인됨: `과정 지속 리스크`

예시:

```markdown
- **윤채은 — 학습 부진 (UI 디자인 실무 만족도 2점)**

  `상황`

  - 실습을 따라가기에 급급해 기능의 적용 이유를 이해하기 어렵다고 응답함.
  - UI 디자인 실무 만족도 2점이 확인됨.

  `운영진 대응 및 결과`

  - 확인된 운영진 대응 내용 없음(수기 보완 필요)
```

설명 텍스트가 없으면 원인을 만들지 않는다. 대신 낮은 점수 항목을 모두 확인해 제목과 상황에 나열한다. 여러 항목이 낮으면 단순히 `UI 디자인 실무 만족도 1점`이라고만 쓰지 않고 `전반적 학습 만족도 저조`로 묶는다.

제목 괄호의 대표 점수는 D/E/G 중 가장 낮은 유효 점수다. 예를 들어 콘텐츠 3점·실시간 4점·과제 2점이면 `(UI 디자인 실무 만족도 2점)`으로 쓴다.

헬스체크 근거가 있으면 `상황`에는 날짜, 차수, 라벨과 확인된 상담 사실을 함께 쓴다. 본문에 `상담 대응`, `최종 안내`, `상담 결과`, `하차방어완료`처럼 운영진 대응이나 결과가 명시되어 있을 때만 `운영진 대응 및 결과`에 넣는다. 대응 내용이 없으면 비워두고 렌더러의 수기 보완 문구를 사용한다.

예시:

```markdown
- **민규 — 수업·운영 불만**

  `상황`

  - 2026-07-28 2차 헬스체크에서 `불만` 라벨이 확인됨.
  - 수업 설명이 지엽적이고 특강 내용/에티튜드가 아쉽다는 의견이 확인됨.
  - 만족도 조사와 과제 업로드 부담, AI 유료 사용 여부에 따른 학습 격차 우려가 확인됨.

  `운영진 대응 및 결과`

  - 확인된 운영진 대응 내용 없음(수기 보완 필요)
```

## 5. Markdown 안전 출력

원문이 `>`, `<`, `#`, `-`, `+`, `*`, `` ` ``, `|` 같은 Markdown 제어문자로 시작해 목록·인용문·표로 오인될 때는 해당 문자 앞에 역슬래시를 붙인다. 보이는 원문 내용은 바꾸지 않는다.

예시:

```markdown
- \>\< 항상 잘 챙겨 주셔서 감사해여
```

빈 목록 항목 뒤에 인용문을 만들거나, 원문을 JSX·HTML·코드블록으로 감싸지 않는다.
